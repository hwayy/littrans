# LitTrans 0.8 implementation contract

Status: implementation on `dev/0.8`, based on 0.7.6 (`5865703`).

## Scope and invariants

Four independently callable coordinator skills: Literature Translation, Source Processor,
Context Manager, Translation Coordinator. Worker instructions have one portable source of
truth: document scout, source reviewer, asset transcriber, asset reviewer, terminology
researcher, translator, translation reviewer (three independent lenses).

Preserve extraction algorithms, layout cache/override replay, original images, project
storage, source fidelity receipts, three translation audit lenses and asset review gates.
Task completion is not content approval. A single-context self-review is not independent
audit. Missing host capabilities produce a fresh-session handoff, never invented evidence.

Codex, Claude Code and OpenCode are targeted hosts. Cursor and Qoder retain general
compatibility. Unknown environments use generic mode. CLI does not call model APIs.
Codex project agents are optional generated configuration, not assumed plugin registration.

## CLI migration

| Existing | Canonical 0.8 entry |
| --- | --- |
| source prepare | source extract |
| batch create/show/refresh | translation batch create/show/refresh |
| qa run | translation qa |
| review ... | translation review ... |
| approve | translation approve |
| render | translation render |
| glossary lookup/check | context glossary lookup/check |

Domain packet/import commands remain available. The task interface wraps domain packets
and validators; it does not replace their schemas. Existing workflow packet bindings remain
readable. All deprecated entries keep parameters, defaults, stdout and exit codes throughout
0.8.x; warnings go to stderr. Historical packets are never rewritten for command spelling.

## Acceptance

Validate standalone source/context/translation requests; original-only delivery followed by
optional transcription; isolated translate/transcribe candidates; three independent audits,
including empty results; revision and stale evidence rejection; idempotent imports; recovery
of saved results; fresh-session handoff; generated configuration conflicts; installed resource
paths; and existing complex-source extraction regressions.

Compare canonical and legacy command behavior on equivalent project states, including
errors, JSON/JSONL stdout and exit codes. New authored instructions use canonical commands.
Do not infer model identity or visual understanding from self-reported hashes/task IDs.

## Release

Development builds use `0.8.0-dev.N`. Project schema and packet protocol versions are
independent of plugin version. Do not release 0.8.0 until the three targeted hosts have real
workflow evidence. Do not claim a host pilot or visual inspection that was not performed.
