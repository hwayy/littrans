# Document structure preparation

This is a preparation stage before extraction, with feedback from source review. It is scoped to the requested source pages; it does not require processing the whole book.

1. Run `source probe PROJECT --pages PAGES`. It reads native line openings, fonts, sizes, line starts and raster counts into `context/source-structure.json`. It creates no units, batches or translations and never overwrites an existing profile: probing further pages appends their observations, keeps the reviewed rules and notes, and sets the status back to `draft` until the rules have been checked against the new pages. These statistics are candidates, not semantic decisions.
2. Inspect original pages selected for diversity: a chapter opening, ordinary prose, a named block and its ending, a page seam, a list, displays, figures/tables/code, and footnotes. Add samples whenever later pages introduce a new layout. Record actual inspected pages and concrete evidence in `review_notes`; set `status: reviewed` only after this inspection. This status describes the preparation profile, not source fidelity.
3. Fill `handling_rules` with the document's own forms, using any additional categories needed. Record heading levels and run-in headings; container start/end cues and proof ownership; indentation and paragraph spacing; lists versus mathematical symbols; prose before/after displays; cross-page continuity; captions and footnotes; multi-column or exceptional layouts. Include counterexamples and unresolved ambiguity. Do not assume every book uses theorem labels, a diamond or a square identically. For lists and exercises, record the label forms the book prints (`1.11.`, `(a)`, bullets) and where their text columns sit; the page ledger's `structure.list_items` shows which labels preparation placed and which chunks it read as continuations (see [fidelity-workflow.md](fidelity-workflow.md), "Prepared units and assets").
4. Scope rules that hold only for some pages. `handling_rules` are the base rules and apply to every page of the profile; a later chapter or appendix that prints new forms gets a `page_rules` block instead of an edit to a base rule: `{"label": "Chapter 2", "pages": "52-67", "handling_rules": {"lists": "- a), b), c) labels …"}}` (`pages` is a page spec inside the profile scope, never `all`; `label` is descriptive only; a block may add a category the base rules lack). The guidance of a page is, per key, the base text followed by the text of every block covering that page, joined by a line break — what a reviewer of that page reads. Source packets embed the profile, page ledgers record the digest of their page's guidance, and a receipt is refused only when the guidance of *its* page changed since the review (the message names the page and the keys); probing more pages, observations, `inspected_pages`, `review_notes`, `status`, block labels and the file's formatting or line endings change nothing. Editing a base rule changes every page's guidance and voids every receipt; a base rule split at a line boundary into a scoped block reads the same and voids none (`source rescope PROJECT --packet source-<id> --pages PAGES` performs that split for the text appended since a packet). The `sha256` in packets and `document_structure` is a content digest of the profile, not the file's bytes.
5. Use these rules while running `source prepare` and making supported `source import-review` corrections. The profile is agent-facing guidance: it does not execute arbitrary code, replace the layout model, merge arbitrary regions, or automatically certify container membership. Preserve original units and geometry; use reviewed parent groups for complete logical scope. Keep paragraph/list/display children within the container.
6. Independently verify actual ownership and structure on every extracted original page. Profile samples do not replace page review. Check closing symbols, formula-following prose, list lead-in breaks, recoverable text bullets, and both sides of each page seam. Record new forms in a `page_rules` block for the pages that print them, create a fresh packet and recheck affected source dependencies. A packet whose guidance for a page changed can no longer be imported for that page; existing source remains unchanged until explicit corrections.
7. Only after source fidelity passes, create batches at complete reviewed parent/continuation boundaries. Budget targets are soft and may be exceeded by an indivisible block. Preserve headings and footnotes with their context. Include the profile rules in downstream context and record oversized blocks rather than splitting them.

For existing projects, add this stage without rebuilding valid source. Describe which pages were already reviewed and which need correction. A source hash mismatch requires a new profile for the new PDF. Never copy a `reviewed` status or source approval from another book.
