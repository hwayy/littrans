# Prepare Literature Source

You coordinate. Page-by-page review and correction run in `literature-source-reviewer` subagents, which follow [source-review.md](references/source-review.md); you do not review pages in your own context. The launcher is described in [runtime.md](../../references/runtime.md) and subagent dispatch per host in [host-runtimes.md](../../references/host-runtimes.md).

1. **Runtime and project.** Run `doctor`. If `layout_runtime` is not `ok`, run `layout install` (`layout install --repair` when the reason asks for it); skip it only at the user's explicit request, then prepare with `--allow-missing-layout`. Never repair the layout environment by hand with `pip` or file moves, and on `AppData redirection` stop and tell the user. Create a project with `project init SOURCE.pdf PROJECT` (`--repo-root DIR` when it is nested in a larger repository), rebuild a pre-v6 project with `project rebuild OLD NEW`, or complete an existing one with `project scaffold PROJECT` (`--refresh` after a plugin upgrade). Once the repository exists, `project tracked PROJECT` confirms git tracks exactly the record. Confirm the per-role models with `project models PROJECT --host HOST`.
2. **Structure profile.** Run `source probe PROJECT --pages PAGES`, inspect representative original pages and complete `context/source-structure.json` as [document-structure.md](../../references/document-structure.md) describes, then set it `reviewed`. For pages added later, probe them, record any new form in a `page_rules` block scoped to exactly those pages, list them in `inspected_pages` and set `reviewed` again. Editing a base rule voids every receipt in the project.
3. **Prepare.** Run `source prepare PROJECT --pages PAGES`. To re-prepare, add `--replace`: it reuses each page's recorded layout result and replays its recorded override. Add `--redetect` or `--discard-overrides` only when the user asks. Every prepared page not in `retained_receipt_pages` needs review, and so does every page in `invalidated_pages`, which names each page, in the run or outside it, whose receipt the run removed. Do not offer extraction modes, and do not edit generated units or asset registries.
4. **Dispatch review.** Split the scope into contiguous page ranges at chapter or section boundaries, about ten pages each. For each range, run `source review-packets PROJECT --pages RANGE --host HOST` and dispatch one fresh `literature-source-reviewer` subagent with the project path, the range, the packet path and the output's `dispatch.model` (on Codex also `dispatch.reasoning_effort`). Run ranges in parallel within the host's wave limit. Give a reviewer no expected verdicts and no other reviewer's report.
5. **Act on the reports.** Each report lists approved pages, blocked pages with reasons, proposed `page_rules`, and pages outside its range whose receipts its corrections invalidated. Record the rules you accept in one edit of the profile, each block scoped to the pages the report names. A page that a report approves although its own proposed rule covers it counts as unreviewed; include it in the next dispatch (once the rule is recorded, its receipt stops verifying anyway). Then dispatch fresh reviewers for those pages, the blocked pages and the invalidated pages. Repeat until `source verify PROJECT --pages PAGES` passes. Keep the source packets that receipts name (`receipt_packets`): they are review dependencies.
6. **Context.** Write `context/document-brief.md` and `context/style-guide.md` as rules only; every audit hashes both files whole. Put hard term gates in `glossary/approved.yaml`. Put proper names kept in source form and one-word-two-senses registers in `glossary/reference.yaml`, each with a `kind`. Put promotion decisions in `glossary/candidates.yaml`. `glossary check` reports entries that match no prepared unit, and `glossary lookup --pages` shows what a range will receive.
7. **Handoff.** Run `source render PROJECT --pages PAGES` and report the verified pages and the checkpoint it writes. Source preparation ends here: do not create batches. The user may still correct the source after reading the checkpoint, and a batch freezes the units, their order and context it was cut from. Batches are cut when the user asks to start translating, as step 1 of `continue-literature-translation` says. Formula transcription is optional and can be scheduled independently at any later time; translation does not wait for it.

Only if the host offers no subagents, run the reviewer procedure in a separate fresh session per range and tell the user about that limitation. Report missing evidence as missing: a page is verified only by a passing receipt, never by a page-sized image, an empty warning list or a detector score.
