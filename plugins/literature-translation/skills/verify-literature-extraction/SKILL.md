# Verify Literature Extraction

The pretranslation gate is faithful, complete source preservation. Use [runtime.md](../../references/runtime.md) and [semantic-contract.md](references/semantic-contract.md).

1. Generate `source review-packets` for the selected pages. Read the packet manifest, source units, asset regions, unassigned glyphs and overlay report, including its bound document-structure profile. Treat profile rules as hypotheses to check against the original; report newly encountered forms and record them in a `page_rules` block for the pages that print them before creating a fresh packet (editing a base rule voids every receipt in the project).
2. Inspect every original page alongside its overlay. Work from the original page outward, including small variables, footnotes, captions, tables, raster labels, running material and blank pages; do not inspect only detected candidates.
3. Check complete document-specific containers and their closing marks, list lead-ins and real text bullets, paragraphs continuing after displays (including “where” clauses), reading order, paragraph and cross-page continuity, equation numbers, `footnote_number`/`footnote_refs` ownership and links, image boundaries and duplicate prose. Whole figures may own their internal mathematics. Preserve uncertain complex regions intact, with an explicit grouping decision, rather than silently discarding them.
   Check semantics unit by unit, not page by page: a unit's `kind` is only as good as the detector box it came from. For every heading, caption and run-in label (theorem, example, proof, step), compare its face, size, indent and the white space around it with the page's running text and with the same form on neighbouring pages — an italic step line, a run-in theorem line or a sentence that mentions a figure ("Figure 10.2 shows …") is a paragraph, not a heading or caption. At every native text block joined into the unit before it, look for a paragraph break (an indent, extra white space, a new item) the join ran over. For every list, follow the chain lead-in → items → displays and explanation paragraphs inside each item; a list container is flat (the lead-in is the parent of all of them), and an item-level parent is an override choice.
4. Return the packet-bound review decisions using its emitted `review-template.json`. Read each page's `context` block first: it lists the declared `formula_conditions`, the `grouping_pending` asset IDs, `boundary_diagnostics`, the `findings` that block approval and the `structure_checks` to confirm one by one, so confirm those lists against the original instead of guessing from crops. Every row of `structure_checks.roles` (headings, captions, run-in labels, overruled detector labels) goes into `confirmed_roles` as `{"unit_id", "kind"}` with the kind you read on the original, and every row of `structure_checks.joins` into `confirmed_joins` as `{"block"}` once you have checked there is no paragraph break at it; a page with an unconfirmed row is rejected, and a kind you read differently (`role-disputed`) is corrected with a `units` override, not confirmed. An asset with a pending grouping decision blocks approval until the decision either corrects it with an override or accepts it in `accepted_grouping_pending` (`asset_id` plus a stated `reason`); language a math crop holds without a declaration (`undeclared-formula-language`) blocks approval until it is declared or the region is split (a `math` region or preserved `math` asset that omits `formula_conditions` is declared automatically; write the list yourself only to overrule it). A rejected page's reasons come back in `rejected_pages` and in the receipt's `failures`. Record source/layout defects precisely. Correct a page by adding an `override` to its decision (`regions`, `units`, `page_canvas_bbox`; contract and example in [fidelity-workflow.md](../../references/fidelity-workflow.md#override-contract)); a corrected page is re-prepared and needs a fresh packet and review. The override replaces the one the page's ledger already records, block by block: carry forward a recorded `units` or `regions` block the new correction does not change, or drop it on purpose with `null` — an import refuses a decision that would silently retire one. A region that owns no glyphs (a rule, a figure frame) is written without `glyph_ids` or with an empty list; both are a raw crop that keeps the declared `kind`. Import through `source import-review` with the required visual-review attestation only after actually inspecting the images. An import refuses a corrected page whose recorded layout result is missing from `derived/fidelity-layout/` rather than re-cutting it by fallback rules; restore the cache or re-detect that page with `source prepare --pages N --replace` and review a new packet.
5. Rerun `source verify`. Fix uncovered source content or stale evidence through supported source corrections and new review packets. Source PDF/region changes invalidate the affected verification; never reuse a receipt with a changed fingerprint. `fidelity-source-unverified` with `source structure guidance changed since review for page N (handling_rules: …)` means the named rules changed for that page since its review — restore them or review the page from a fresh packet; the file's line endings or formatting never cause it. An import reports every page it invalidated: `changed_pages` (corrected), `deferred_pages` (in the review, dependency moved) and `invalidated_pages` (outside the review, dependency moved) all need a fresh packet. The packets that verified receipts name (`receipt_packets`) are review dependencies: never delete them as leftovers.
6. Run `source render PROJECT --pages PAGES` and read the checkpoint HTML (`output/source-pNNNN-pNNNN.html`) as a document: headings, figures with captions, list items, displayed lines and inline notation must read in order with tight original images. Any defect still visible there goes back through `source import-review`; only then create batches or hand the pages to a translator. Add `--standalone` when the checkpoint is to be shared as one file (assets embedded).

A faithful original image may pass while its LaTeX remains unfinished. Missing mathematical understanding belongs in translation uncertainties; it is different from missing source content. Do not infer zero omissions from aggregate detector scores or an enclosing page box.

For a math asset with source-native words (a displayed cases formula's condition words, an inline `i.o.` or `a.s.`), review its `formula_conditions` entries (ordered original `glyph_ids` plus exact `source_text`) as the template's `context.formula_conditions` lists them. The words are inside the crop by construction — a declared condition is always owned by the asset — so the question is whether each declaration is correct and whether any language in the crop is missing, not whether the words lie outside the image. Confirm that before setting `formula_conditions_checked`. These assets require translated companions even though their mathematical image remains intact.

When original content-stream ink lies beyond the PDF page box, a source override may specify `page_canvas_bbox` to expand an unrotated origin-zero page in memory. Inspect the original page, the separately hashed overflow canvas image, and the recovered fragment before setting `overflow_canvas_checked`. This does not rewrite the source PDF or reconstruct missing characters. Reject arbitrary canvas expansion without existing off-page native glyphs.
